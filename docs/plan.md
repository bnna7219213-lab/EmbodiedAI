## 第 0 章：具身智能体技术全景与现状审计

> 理解"具身智能"在当下技术栈中的位置，搞清楚我们能做什么、不能做什么、必须先做什么。

### 0.1 具身智能体定义

具身智能（Embodied AI）= 智能体拥有物理身体，通过传感器感知物理世界，
通过执行器作用于物理世界，通过神经网络（或多模态大模型）做决策。

核心公式：

```
环境 → 感知(摄像头/力传感器/IMU) → 决策(神经网络) → 执行(电机/液压) → 环境
```

### 0.2 具身智能技术栈分层

```
L6 应用层：家庭服务 / 工业装配 / 医疗护理
L5 模型层：VLA (Vision-Language-Action) / 端到端行为克隆 / 大模型规划
L4 中间件：ROS2 / Isaac Sim / MuJoCo（仿真-真实迁移）
L3 操作系统：实时 Linux (PREEMPT_RT) / Zephyr RTOS
L2 驱动层：电机驱动 / 传感器融合 / 通信总线
L1 PCB/硬件层：主控板 / 传感器板 / 电机驱动板 / 电源板
L0 机械结构层：关节 / 连杆 / 外壳 / 柔性结构
```

## 第 1 章：端到端 AI 模型研发计划（神经网络）

> 参照 LLMInnovation 的自研路线，但面向具身智能做关键调整：
> 不只是语言模型，而是 **VLA（Vision-Language-Action）** 模型。

### 1.1 模型架构选型

具身智能的 AI 模型有三种路线：

```
路线 A：分治方案
  视觉模型 + 语言模型 + 独立运动规划器
  优点：模块化，团队可并行
  缺点：模块间接口损失信息，端到端优化困难

路线 B：端到端 VLA（推荐）
  单一模型接收 [图像, 语言指令, 本体感受] → 直接输出关节角度/力矩
  优点：全局优化，自然流畅
  缺点：数据需求大，训练难度高

路线 C：混合方案（优先落地）
  大模型做高层规划（"去厨房拿杯子"）+ 低层控制器做精确执行
  优点：大模型不必精确到关节，低层可用传统控制
  缺点：仍存在层次间接口
```

**自研选择**: 路线 C（混合）作为 Phase 1-2 落地目标，路线 B（端到端 VLA）作为 Phase 3+ 长期目标。

### 1.2 Phase 1: 基础 VLM 后端（4 周）

目标：搭出一个能"看 + 说 + 理解指令"的基础模型。

```
架构: VLM (Vision-Language Model)
  Vision Encoder: ViT-B/16（从图像中提取 16 个视觉 token）
  LLM Backbone: 3B Transformer（参照 LLMInnovation Phase 1 配置）
  输出: 高级语义指令（如"抓取红色杯子"）

训练数据:
  - 视觉: COCO / Open Images 物体检测 + 场景理解
  - 指令: 人工标注 10K (图像, 指令) 对
  - 动作映射: 指令 → 预定义动作基元（抓取/放置/移动）

关键文件:
  src/models/vlm/vision_encoder.js   — ViT-B/16 视觉编码器
  src/models/vlm/vlm.js             — VLM 融合模型
  src/models/vlm/action_head.js     — 动作基元输出头
  data/instruction_10k.json         — 训练数据
```

**与 LLMInnovation 的差异**: 不追求 100B 规模，优先做 3B 可实时推理的轻量 VLM。
推理延迟目标 < 50ms（Orin 级硬件）。

### 1.3 Phase 2: 电机指令生成网络（6 周）

目标：从高级语义到电机控制信号的完整映射。

```
输入: [视觉 token, 语言指令, 当前关节角度(12维), 力传感器读数(6维)]
      ↓
  语义规划器 (VLM Phase 1 输出)
      ↓
  动作序列: ["移动到杯子上方", "下降", "闭合手爪", "提升"]
      ↓
  运动翻译器 (Transformer decoder-only, 200M 参数)
      ↓
  关节角度序列: [θ1(t), θ2(t), ..., θ12(t)], t=0..T (T=100步, 10Hz)

运动翻译器关键:
  - Decoder-only, 自回归输出
  - 条件输入: 动作序列 token + 当前本体感受
  - 输出: 每个时间步的 12 个关节角度
  - 损失: L2 on joint angles + 末端执行器位置 L2
```

### 1.4 Phase 3: 端到端 VLA（长期目标，12+ 周）

```
架构 (Helix 风格):
  输入: 多视角图像 + 语言指令 + 本体感受历史
    ↓
  Vision Encoder (提取空间特征)
    ↓
  Language Encoder (提取语义)
    ↓
  状态编码器 (关节角度/速度/力矩)
    ↓
  融合 Transformer (跨模态注意力)
    ↓
  动作 Tokenizer (离散化关节角度 → token ID)
    ↓
  自回归解码 → 动作 token 序列
    ↓
  Detokenizer → 连续角度命令 → 硬件执行

推理频率: 20 Hz (每 50ms 输出一次动作)
模型大小: 7B（推理时可 INT4 量化到 ~4GB）
```

### 1.5 训练数据管线

具身智能的核心瓶颈是数据，不是算法。

| 数据类型 | 获取方式 | 规模目标 |
|---|---|---|
| 人类示范数据 | 遥操作（VR 手柄 / 外骨骼示教） | 100 小时 |
| 仿真合成数据 | Isaac Sim + 域随机化 | 100 万条轨迹 |
| 公开数据集 | Open X-Embodiment 子集 | 50 万条轨迹 |
| 自采集 | 实际机器人执行 + 成功/失败标注 | 10 万条轨迹 |

```
数据格式 (每条轨迹):
{
  "observations": [
    {"image": "cam_top/0001.jpg", "joints": [...], "forces": [...]},
    ...
  ],
  "actions": [θ1, θ2, ..., θ12],   # 每个时间步的关节角度
  "instruction": "pick up the red cup",
  "success": true,
  "robot_model": "embodied_v1",
  "collect_method": "teleop_vr"
}
```

## 第 3 章：自动关机电机驱动 — 硬件安全设计专题

> **核心问题**: 如何让电机在异常情况下（过流/过温/通信丢失/碰撞检测）
> 不依赖软件关断，而是硬件级在 < 1ms 内自动切断电源？

### 3.1 为什么软件关机不够

```
软件关机路径:
  异常 → MCU 中断 → 判断 → GPIO 拉低 → 预驱动关断 → MOSFET 截止
  延迟: 1~10 ms (中断延迟 + 上下文切换 + 判断逻辑)

硬件关机路径:
  异常 → 比较器触发 → 硬件锁存 → MOSFET 截止
  延迟: < 1 μs (纯硬件路径)

差距: 1000x。电机在 1ms 内短路电流可达稳态的 5-10 倍。
```

### 3.2 自动关机硬件架构

```
                    V_MOTOR (48V)
                        │
                   ┌────┴────┐
                   │ MOSFET   │ ── 高侧开关
                   │ (Q1-Q3) │
                   └────┬────┘
                        │
              ┌─────────┼─────────┐
              │   电机三相 (U V W)  │
              └─────────┼─────────┘
                        │
                 ┌──────┴──────┐
                 │  低侧 MOSFET  │ ── Q4-Q6
                 │  + 电流采样  │ ── R_shunt ── INA240
                 └──────┬──────┘
                        │
                    ════ GND

  自动关机信号源:
    ┌──────────────────────────────────────────────┐
    │ ① 过流检测: INA240 → 比较器 (阈值 30A)       │
    │    └→ 触发窗口: < 1μs                        │
    │                                               │
    │ ② 过温检测: NTC 分压 → 比较器 (阈值 85°C)     │
    │    └→ 触发窗口: ~10ms (热惯量大)              │
    │                                               │
    │ ③ 通信守时狗: MCU 心跳消失 > 50ms              │
    │    └→ 硬件看门狗 TPS3808 → 自动关断           │
    │                                               │
    │ ④ 碰撞检测: 力矩传感器 > 阈值 OR 加速度突变    │
    │    └→ 快速比较器 → 关断 (峰值力限制)           │
    │                                               │
    │ ⑤ 紧急按钮: 外部硬线 → 光耦隔离 → 关断        │
    │    └→ 手动最高优先级                          │
    └──────────────────────────────────────────────┘
                        │
                        ▼
              ┌─────────────────┐
              │  硬件锁存器      │ ─ 触发后保持关断状态
              │  (SR Latch)     │    需 MCU 清除
              └────────┬────────┘
                       │
              ┌────────▼────────┐
              │  栅极驱动关断    │ ─ DRV8301 GHx/GLx 拉低
              │  (Gate Disable) │    ~200ns 响应
              └─────────────────┘
```

### 3.3 自动关机电路详图

**过流保护 (核心)**:

```
              V_MOTOR (48V)
                  │
             ┌────┴────┐
             │  Q1      │ ← 高侧 MOSFET (BSC016N06NS)
             │  (高侧)  │
             └────┬────┘
                  ├──→ Motor U
             ┌────┴────┐
             │  Q4      │ ← 低侧 MOSFET
             │  (低侧)  │
             └────┬────┘
                  │
             R_shunt (1mΩ)
                  │
             ═════╧═════ GND

  电流采样电路:
    R_shunt 两端电压 = I × 1mΩ
    例如 30A → 30mV

    INA240 (增益 20V/V):
      30mV × 20 = 0.6V (输出到比较器)

    比较器 TLV3201 (推挽输出, 40ns 响应):
      V_ref = 0.6V (对应 30A 过流阈值)
      V_sense > V_ref → 输出高 → 硬件锁存触发

    MCU 可配置阈值 (DAC 或 PWM + LPF):
      通过 SPI 控制数字电位器 → 调节 V_ref
      → 不同关节可设不同过流阈值 (肩关节 > 腕关节)
```

**硬件看门狗 (Communication Watchdog)**:

```
  MCU 心跳:
    STM32 GPIO ──→ 555 单稳态 ──→ 看门狗输入
    (每 10ms 一个脉冲)
                  │
                  ▼ (心跳消失超过 50ms)
             ┌────────────┐
             │ TPS3808    │ ─ 可编程延时
             │ 窗口看门狗  │   (SET0/SET1 接 RC)
             └─────┬──────┘
                   │ RST 低
                   ▼
           栅极驱动封锁
           电机立即停止
           需人工复位才能恢复
```

### 3.4 自动关机 PCB 布局要点

```
四层 PCB 堆叠 (电机驱动板):
┌──────────────────────────┐
│ Top: 功率层 (MOSFET + 电流采样) │
│  ─ 大电流铺铜, 50mil 走线       │
├──────────────────────────┤
│ Inner1: 地平面 (完整地平面)     │
│  ─ 不切割, 最小化回流路径        │
├──────────────────────────┤
│ Inner2: 信号/电源层            │
│  ─ 栅极驱动信号, 隔离电源        │
├──────────────────────────┤
│ Bottom: 控制层 (MCU + 比较器)   │
│  ─ 自动关机电路集中在此          │
└──────────────────────────┘

布局优先级:
  1. 电流采样路径最短 (从 R_shunt 到 INA240 < 5mm)
  2. 比较器到锁存器到栅驱路径最短 (< 10mm)
  3. 功率地与控制地单点连接
  4. 栅极驱动走线宽度 ≥ 15mil, 远离信号线
```

## 第 4 章：从硬件角度设计具身智能体（PCB 依赖全景）

> 这章回答核心问题: "设计一个具身智能体，PCB 还需要依赖什么？"

### 4.1 PCB 之外的五层依赖

PCB 是具身智能体的"骨架和神经"，但骨架之外还需要：

```
层级 1: PCB 自身           → 基板 + 铜箔 + 阻焊 + 沉金
层级 2: 器件焊接           → SMT + 回流焊 + X-Ray 检测
层级 3: 线缆与互联         → FPC / 排线 / 同轴线
层级 4: 结构件依赖         → 散热器 + 支架 + 密封
层级 5: 执行器与传感器     → 电机 + 减速器 + 编码器 + 摄像头
```

### 4.2 详细 PCB 依赖清单

#### 4.2.1 PCB 基板材料

| 部位 | 基材 | 理由 |
|---|---|---|
| 电机驱动板 | FR-4 高 Tg (Tg170) | 耐热 + 耐振动 |
| 传感器板 (柔性部分) | 聚酰亚胺 (PI) 柔性板 | 贴合曲面关节 |
| 高速信号板 | Rogers RO4350B | 低损耗, 适合 > 1GHz |
| 散热区域 | 铝基板 (MCPCB) | MOSFET 散热 |

#### 4.2.2 SMT 贴装依赖

```
PCB裸板
  → SMT 锡膏印刷 (锡膏: SAC305 无铅)
  → SPI (锡膏检测)
  → 高速贴片机 (0402/QFN/BGA)
  → 回流焊 (峰值 245°C)
  → AOI (自动光学检测)
  → X-Ray (BGA/QFN 底部焊点)
  → ICT/FCT (在线测试/功能测试)
  
关键注意:
  - BGA (如 Orin 模组) 需 X-Ray 检测
  - 高电流路径需增加焊锡厚度或加锡
  - 振动环境需底部填充胶 (Underfill)
```

#### 4.2.3 线缆与柔性连接

```
柔性电路板 (FPC) 用途:
  - 旋转关节供电 (滑环替代方案: 柔性螺旋线)
  - 头部摄像头到主板 (MIPI 差分, 需阻抗匹配)
  - 手指触觉到手腕 (多路模拟信号, 需要屏蔽)

连接器选型:
  - 板对板: DF40 系列 (Hirose, 0.4mm pitch, 超薄)
  -  FPC: FH12 系列 (0.5mm pitch, 抽屉式锁紧)
  - 电源: XT60 / XT90 (大电流), JST GH (小电流信号)
  - 通信: M12 防水连接器 (工业以太网)
```

#### 4.2.4 结构件协同

```
PCB 与结构的协同设计:
  
  ┌─────────────── 铝合金关节外壳 ──────────────┐
  │                                             │
  │   ┌─────────┐                              │
  │   │ PCB      │ ← 四角螺孔固定到铝壳          │
  │   │ (4层)    │   (M2.5 螺钉 + 绝缘垫片)     │
  │   │          │                              │
  │   │ MOSFET ──┼──→ 导热硅胶垫 → 铝壳散热     │
  │   └─────────┘                              │
  │                                             │
  │   ┌─────────────┐                          │
  │   │ 无刷电机     │ ← 铝合金壳体               │
  │   │ (外转子)     │   (散热 + 磁路)            │
  │   └─────────────┘                          │
  └─────────────────────────────────────────────┘

关键协同:
  - PCB 的安装孔位与结构件协同设计 (避免干涉)
  - MOSFET 散热面贴合外壳 (导热垫 + 螺丝扭矩控制)
  - 连接器开孔位置对齐 ±0.2mm
  - 电磁兼容: PCB 接地点与外壳低阻抗连接
```

### 4.3 具身智能体 PCB 设计的六个特殊约束

| 约束 | 原因 | 应对 |
|---|---|---|
| **空间极小** | 关节/手臂内部空间有限 | 刚柔结合板 + 高密度互连 (HDI) |
| **振动冲击** | 机器人运动带来持续振动 | 螺钉固定 + Underfill + 连接器锁扣 |
| **散热受限** | 封闭外壳内空气不流通 | 导热垫直连外壳 + 铝基板 |
| **EMC 要求** | 电机 PWM 产生强干扰 | 屏蔽壳 + 滤波 + 分割地 |
| **可维修性** | 关节模块需独立更换 | 模块化 PCB + 快插连接器 |
| **重量敏感** | 每克影响负载和能耗 | 铝基板 + 结构复用 + 减薄板 |

## 第 5 章：神经网络模型到硬件执行的编译映射

> 训练好的 AI 模型如何变成电机旋转？这是整个链条中最易被忽略的一环。

### 5.1 编译流水线

```
PyTorch/自研模型
       │
       ▼
  ONNX 导出 (算子图)
       │
       ▼
  图优化 (常量折叠 / 算子融合 / 死代码消除)
       │
       ▼
  TensorRT / ONNX Runtime / TFLite (目标运行时)
       │
       ▼
  量化 (FP32 → INT8 / INT4)
       │
       ▼
  设备可执行文件 (Jetson .engine / Cortex-M .bin)
       │
       ▼
  硬件推理引擎 (周期性执行: 20Hz)
       │
       ▼
  推理输出: 目标关节角度 [θ1..θ12]
       │
       ▼
  FOC 控制环路 (电流环 10kHz / 位置环 1kHz)
       │
       ▼
  PWM 输出 → 三相逆变器 → 电机转动
```

### 5.2 实时性保证

```
时序预算 (20Hz 控制周期 = 50ms):

  ┌──────────────────────────────────────────────────┐
  │ 0ms   5ms   10ms   15ms   20ms   25ms   30ms    │
  │ ├─┼──────────────┼──────────────────┼──────┤     │
  │ │传感│   AI 推理     FOC 计算    │ 安全监测 │     │
  │ │采集│   (VLM+翻译)  (12关节并行)│ (同步)  │     │
  │ │1ms │   ~15ms       ~5ms        │ ~2ms   │     │
  │ └─┴──────────────┴──────────────────┴──────┘     │
  │                                                    │
  │ 剩余 ~27ms: 系统裕量 (通信/日志/安全狗)            │
  └────────────────────────────────────────────────────┘

控制环路频率分配:
  AI 推理:       20 Hz  (每 50ms 更新目标角度)
  位置环:        1 kHz  (1ms 周期, 跟踪目标角度)
  速度环:        1 kHz  (位置环内嵌)
  电流环 (FOC):  10 kHz  (100μs 周期, 最内环)
  自动关机监测:  1 MHz  (比较器级别, 纯硬件)
```

### 5.3 FOC 控制到 PWM 输出的完整链路

```
目标角度 θ_target (来自 AI 模型)
       │
       ▼
  ┌──────────┐
  │ PID 位置环│ → 目标速度 ω_target
  └────┬─────┘
       ▼
  ┌──────────┐
  │ PID 速度环│ → 目标电流 Iq_target
  └────┬─────┘
       ▼
  ┌──────────────────┐
  │ Clark + Park 变换 │ (三相电流 → dq 轴电流)
  │ dq PID 电流环     │ → Vd, Vq 电压
  │ 反 Park 变换      │ → Vα, Vβ
  │ SVPWM 调制        │ → 三路 PWM 占空比
  └────────┬─────────┘
           ▼
  ┌──────────────────┐
  │ 栅极驱动器        │ → 6 路 PWM → 6 个 MOSFET
  │ + 自动关机硬件    │ ← 过流/过温直接关断
  └──────────────────┘
           ▼
      电机三相电流 → 转子转动 → 编码器反馈
```

## 第 10 章：强化学习 — 具身智能体的决策核心

> 强化学习的本质不是"教"机器人怎么做, 而是让机器人通过"试错"自己发现最优策略。

### 10.1 数学本质: MDP

详见 [docs/reinforcement-learning.md](reinforcement-learning.md) 全文。

核心公式:

```
贝尔曼方程:
  Q*(s,a) = E[ R(s,a,s') + γ · max_a' Q*(s',a') ]
              └──────────────┘   └──────────────────────┘
              即时奖励               折扣后的最优未来

策略梯度:
  ∇J(θ) = E[ ∇_θ log π_θ(a|s) · Q^π(s,a) ]
           └──────────────────┘   └──────────┘
            "往好的方向走一步"      "这个动作好到什么程度"

PPO 裁剪目标:
  L = min( r·A, clip(r, 1-ε, 1+ε)·A )   ← ε=0.2, 限制策略变化幅度
```

### 10.2 具身智能 RL 的特有挑战

| 挑战 | 传统 RL | 具身智能 RL |
|---|---|---|
| 动作空间 | 离散 (上下左右) | 连续 (12+ 维关节目标角度) |
| 奖励延迟 | 游戏每步都有奖励 | 可能 50 步后才知成败 |
| 样本来源 | 仿真 (无限) | 真实 (昂贵且耗时) |
| 安全 | 无所谓 | 不允许导致撞人/自毁 |
| 环境 | 静态 (游戏规则固定) | 动态 (物理世界实时变化) |

### 10.3 训练管线

```
人类示教 + 仿真数据
        │
        ▼
┌──────────────────────────────────┐
│ 阶段 1: 行为克隆 (BC)             │
│ - 监督学习模仿人类                │
│ - Loss: cross_entropy / L1        │
│ - 结果: 复现 50-70%              │
└───────────────┬──────────────────┘
                │ 不够, 需要超越
                ▼
┌──────────────────────────────────┐
│ 阶段 2: DAgger                    │
│ - 收集当前策略的状态分布          │
│ - 人类在线标注"正确动作"          │
│ - 迭代 (收集-标注-训练)           │
│ - 结果: 80%+                     │
└───────────────┬──────────────────┘
                │ 需要更优
                ▼
┌──────────────────────────────────┐
│ 阶段 3: PPO / SAC 在线 RL         │
│ - 在仿真中大规模探索              │
│ - 域随机化堵死 sim-to-real gap    │
│ - 奖励函数引导自我改进            │
│ - 结果: 可能超越人类表现          │
└───────────────┬──────────────────┘
                │ 部署
                ▼
┌──────────────────────────────────┐
│ 阶段 4: 在线适应 (Online Adapt)   │
│ - 转移到真实机器人               │
│ - 少量真实样本微调               │
│ - 持续使用持续学习 (终身学习)     │
└──────────────────────────────────┘
```

### 10.4 LLM + RL 融合 (VLA 架构)

```
宏观规划 (LLM, 1Hz)          中观决策 (RL/PPO, 20Hz)
┌─────────────────┐          ┌──────────────────────┐
```

## 第 11 章：触觉传感 — 具身智能体最稀缺的感知

> 当前具身机器人领域更稀缺的是决策算法、传感器、动力学模型。即——触觉。

### 11.1 为什么触觉稀缺

详见 [docs/tactile-sensing.md](tactile-sensing.md) 全文。

核心原因:
```
视觉: $20 摄像头 → 算法成熟 → 数据充足 → 非接触
触觉: $500+ 传感器 → 算法原始 → 数据稀缺 → 接触必磨损
```

### 11.2 传感器路线

| 传感器类型 | 分辨率 | 成本 | 适用 | 可靠性 |
|---|---|---|---|---|
| 应变片六轴力矩 | N/A (6维) | $2000+ | 腕力控 | ★极好 |
| 电容触觉阵列 | 中 | $500-2000 | 面板 | 好 |
| GelSight 光学 | 极高(μm) | $300-3000 | 指尖 | 中 |
| MagTac 磁性 | 高 | $1000+ | 皮肤 | ★极好 |
| 压阻 DIY | 低 | <$50 | 简单检测 | 差 |

### 11.3 触觉与 RL 的集成

```
触觉信号作为 RL 的关键状态维度:

state_s = [joints; imu; vision_token; tactile_feature]
                                               ↑
                                       触觉 CNN/ViT 编码

触觉码 → RL 奖励:
  - 接触力合适 → +r  (指导力控)
  - 检测到滑脱 → -r  (避免失败)
  - 力超限 → -r, 停止 (保护物体/人)
```

## 第 8 章：验证评估体系与风险分析

### 8.1 模型评估

| 评估项 | 方法 | Phase 通过标准 |
|---|---|---|
| 感知准确率 | COCO 物体检测 mAP | AP > 0.60 |
| 指令遵循 | 预定义指令集成功率 | > 80% |
| 行为克隆 | 模仿任务成功率 | > 60% (Phase 1) |
| 端到端任务 | 多步骤任务完成率 | > 40% (Phase 2) |
| 零样本泛化 | 未见任务完成率 | > 30% (Phase 3) |
| 推理延迟 | 端到端 ( 感知 + 决策 ) | < 50ms |

### 8.2 硬件评估

| 评估项 | 方法 | 通过标准 |
|---|---|---|
| 电机控制精度 | 角度阶跃响应 | 稳态误差 < 0.5° |
| 力控精度 | 力传感器标定 | 线性度 < 1% FS |
| 自动关机响应 | 示波器测 MOSFET Vgs | < 1μs (过流) |
| 连续运行 | 72 小时循环测试 | 无故障 |
| 温升 | 红外热成像 | 热点 < 85°C |
| EMC | 传导 + 辐射发射测试 | 符合 EN55032 |

### 8.3 风险登记

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| AI 模型收敛慢 | 高 | 高 | 先做行为克隆 (监督学习) 再过渡到端到端 |
| 自动关机误触发 | 中 | 低 | 可调阈值 + 锁存重启机制 |
| 传感器噪声过大 | 中 | 中 | 多传感器融合 + 卡尔曼滤波 |
| 结构件共振 | 中 | 中 | 模态分析 + 阻尼减振 |
| 训练数据不足 | 高 | 高 | 仿真数据 + 域随机化 + 公开数据 |
| EMC/EMI 超标 | 中 | 中 | 屏蔽设计 + 预测试 + 预留整改空间 |
| 电机退磁 | 低 | 高 | 温度监测 + 过流保护 + 磁钢选型余量 |

### 8.4 安全认证路径

```
面向产品的安全要求:
  - 机械安全: ISO 10218 (工业机器人)
  - 功能安全: IEC 62304 (软件) / ISO 13849 (控制系统)
  - EMC: EN 55032 / EN 61000-6-2
  - 电池: UN38.3 / IEC 62133
  - 家用: CCC (中国) / CE (欧盟) / FCC (美国)
  
Phase 0-1: 不追求认证, 只追求功能正确
Phase 2:   开始预扫 EMC, 识别整改点
Phase 3:   正式认证规划
```
