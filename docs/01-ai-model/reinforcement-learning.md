# 强化学习深度理论 — 具身智能体的决策核心

> 本文档回答核心问题: "强化学习的本质是什么？它如何驱动具身智能体？"
>
> 关键词: MDP、贝尔曼方程、策略梯度、Actor-Critic、PPO、SAC、具身智能应用

---

## 第 1 部分：强化学习的本质理解

### 1.1 核心思想

强化学习不是"教"机器人怎么做, 而是让机器人通过"试错"自己发现最优策略。

```
传统编程:        if 距离 < 0.1m then 抓取    → 穷举规则, 脆弱
监督学习:        给 1000 张图, 标注"夹爪应在这" → 需要标注, 分布外失效
强化学习:        "试试夹住这个杯子, 成功加分, 失败扣分"  → 自己探索, 自适应
```

**类比**: 训练狗做动作。你不需要精确知道狗的每块肌肉如何收缩。
你做的是: 狗做对了 → 给零食 (奖励), 狗做错了 → 不给 (惩罚)。狗自己学会"做什么得到零食"。

具身智能同理: 不需要为每种情况写规则。让机器人在真实或仿真环境中尝试,
有用行为得到正奖励, 无用行为得到负奖励 (或零奖励), 最终自主学习行为策略。

### 1.2 马尔可夫决策过程 (MDP) — 强化学习的数学基础

MDP 是强化学习的数学形式化, 包含四个要素:

```
MDP = (S, A, P, R)

S (State, 状态):     机器人能观测到的所有可能情形的集合
A (Action, 动作):    机器人能执行的所有可能动作的集合
P (Transition, 转移): P(s'|s,a) — 在状态 s 执行动作 a 后, 转移到状态 s' 的概率
R (Reward, 奖励):     R(s,a,s') — 在状态 s 执行动作 a 转移到 s' 获得的即时奖励
```

**具身智能体的 MDP 对应**:

```
S (状态) = 机器人所有可能的感知:
  - 关节角度 (12维): [θ1, θ2, ..., θ12]
  - 关节速度 (12维): [ω1, ω2, ..., ω12]
  - 关节力矩 (12维): [τ1, τ2, ..., τ12]
  - 视觉特征 (ViT token): [v1, v2, ..., v64]
  - 触觉读数以: [f1, f2, ..., fN]
  - 本体感觉: 加速度 + 角速度 (IMU)
  → 共 ~100+ 维状态向量

A (动作) = 所有可能的执行器命令:
  - 目标关节角度: [θ1_target, ..., θ12_target]
  - 或目标力矩: [τ1_target, ..., τ12_target]
  - 手爪开合度: gripper_position
  → 共 12-13 维连续动作

P (转移) = 物理世界的动力学:
  - 包括: 摩擦 / 碰撞 / 变形 / 延迟 / 噪声
  - 通常未知, 机器人通过与环境交互"学习"转移规律
  - 仿真中的 P_sim ≠ 真实 P_real (这就是"仿真-现实鸿沟")

R (奖励) = 任务成功程度的量化:
  - 杯子被抓到? R = +1 (成功)
  - 杯子掉了?   R = -0.5 (失败)
  - 每步时间惩罚: R += -0.01 (鼓励快速完成)
  - 力过大惩罚: R += -0.1 × max(0, force - threshold) (保护物体)
  - 平滑度奖励: R += -0.001 × ||a_t - a_{t-1}||² (动作连贯)
```

### 1.3 与其他学习范式的根本区别

```
┌───────────────┬───────────────────┬────────────────────┬──────────────────┐
│               │ 监督学习           │ 无监督学习          │ 强化学习          │
├───────────────┼───────────────────┼────────────────────┼──────────────────┤
│ 训练信号      │ 标准答案 (标签)    │ 无                  │ 奖励 (标量)       │
│               │ "这是猫"           │                     │ "做得好, +1"     │
├───────────────┼───────────────────┼────────────────────┼──────────────────┤
│ 数据来源      │ 标注过的静态数据集  │ 无标注数据           │ 与环境实时交互     │
├───────────────┼───────────────────┼────────────────────┼──────────────────┤
│ 学习目标      │ 输入→输出的映射    │ 数据内在结构         │ 最优行为策略      │
│               │ f(x) ≈ y           │ 聚类/降维/生成       │ π*(a|s)          │
├───────────────┼───────────────────┼────────────────────┼──────────────────┤
│ 反馈延迟      │ 立即 (每条样本)    │ 无                   │ 延迟 (整条轨迹)   │
│               │                   │                     │ 抓杯子: 走20步才知成败│
├───────────────┼───────────────────┼────────────────────┼──────────────────┤
│ 典型算法      │ CNN, Transformer  │ K-Means, VAE, GAN   │ PPO, SAC, DQN    │
├───────────────┼───────────────────┼────────────────────┼──────────────────┤
│ 与具身关系    │ 训练感知模型       │ 发现运动模式         │ ★ 训练决策核心 ★  │
│               │ (识别物体)        │ (无监督技能发现)     │ (学会如何行动)    │
└───────────────┴───────────────────┴────────────────────┴──────────────────┘

关键洞察: 
  监督学习 = "看别人怎么做的, 模仿" (行为克隆)
  强化学习 = "自己试, 后果自负, 凭经验改进" (真正的智能)
  
  具身智能的难点: 监督学习只能複製人类示范, 无法超越;
  强化学习可以自己发现比人类更优的策略。
```

## 第 2 部分：关键理论支柱

### 2.1 贝尔曼方程 — 将长期决策分解为递归子问题

贝尔曼方程是强化学习最重要的数学工具, 将"长期最优"分解为"即时奖励 + 最优的未来"。

```
贝尔曼方程 (Bellman Equation):

  Q*(s,a) = E[ R(s,a,s') + γ × max_{a'} Q*(s',a') ]
             ───────────────     ──────────────────────
              即时奖励              折扣后的最优未来价值

  其中:
    Q*(s,a) = 在状态 s 执行动作 a 后的最优累积折扣回报
    γ (gamma) = 折扣因子, 0 ≤ γ < 1 (通常 0.95-0.99)
    E[...] = 期望 (因为转移可能有随机性)
```

**直观理解**:

```
想象你在玩一个游戏, 每一步:
  1. 获得即时奖励 r_t (吃到金币 +1, 撞到墙 -1)
  2. 游戏继续, 你希望从下一步开始的最优回报是 V*(s_{t+1})

  那么当前状态的总价值 = r_t + γ × V*(s_{t+1})
  
  为什么要折扣 γ?
    - 不确定性: 越远的未来越不可靠
    - 数学保证: γ < 1 保证无限时间步的总回报有限
    - 人类直觉: 今天的 1 元 > 明年的 1 元
  
具身智能例子:
  "抓取杯子" 任务:
    第1步: 手移动到杯子上方 (r = 0)
    第2步: 手向下 (r = 0)
    第3步: 夹住杯子 (r = 0.2, 触觉检测到接触)
    第4步: 提起杯子 (r = 1.0 成功!)
    
  Q*(初始状态, 开始抓取) = 0 + γ×0 + γ²×0.2 + γ³×1.0 ≈ 0.95³×1.0 = 0.857
  
  如果失败 (拿了空):
  Q*(初始状态, 那个动作) = 0 + γ×0 + γ²×(-0.5) + γ³×(-1.0) = -1.24 → 下次不选这个动作
```

**贝尔曼最优方程与策略迭代**:

```
贝尔曼最优方程 (用于价值迭代):

  V*(s) = max_a Σ P(s'|s,a) × [ R(s,a,s') + γ V*(s') ]

  含义: 最优状态价值 = 对所有可能的动作取最优

策略迭代 (Policy Iteration):
  ┌──────────────────────────────────────────┐
  │ Repeat:                                   │
  │   1. 策略评估: 用贝尔曼方程计算当前策略的价值 │
  │   2. 策略改进: 对每个状态, 选使 Q 最大的动作 │
  │ Until 策略不再变化                          │
  └──────────────────────────────────────────┘

  具身应用: 
    策略评估 = "按照当前策略执行 1000 次, 平均能拿多少分?"
    策略改进 = "在状态 s, 动作 a 比动作 b 平均多拿了 0.3 分, 改用 a"
```

### 2.2 策略梯度 (Policy Gradient) — 直接优化策略

策略梯度方法直接优化策略 π(a|s) 的参数 θ, 使其期望回报最大化。

```
策略 (Policy): π_θ(a|s)
  - 输入: 状态 s (机器人观测)
  - 输出: 动作 a 的概率分布 (连续动作→高斯分布均值/方差)
  - 参数: θ (神经网络的权重)

策略梯度定理 (Policy Gradient Theorem):

  ∇_θ J(θ) = E[ ∇_θ log π_θ(a|s) × Q^π(s,a) ]
              ──────────────     ──────────────
              策略的对数梯度      该动作的实际价值

  含义: 如果动作 a 在实际执行中获得了高于平均的回报 (Q 大),
       则增大在状态 s 下选择 a 的概率;
       回报低, 则减小概率。
```

**三大策略梯度算法对比**:

```
┌──────┬────────────────────────────────────────┬────────────────────┐
│ 算法  │ 核心机制                                │ 适用场景           │
├──────┼────────────────────────────────────────┼────────────────────┤
│      │ 限制新旧策略的"距离"变化                  │ 具身首选 (默认)     │
│ PPO  │ ratio = π_new(a|s) / π_old(a|s)        │ 训练稳定            │
│      │ clipped: 裁剪 ratio 到 [1-ε, 1+ε]      │ 超参数不敏感        │
│      │ 目标: L = min(ratio×A, clip(ratio)×A)  │ OpenAI 默认 RL 算法 │
├──────┼────────────────────────────────────────┼────────────────────┤
│      │ 用 KL 散度约束策略变化                    │ 对稳定性要求高      │
│ TRPO │ max E[A] s.t. KL(π_old, π_new) < δ      │ 计算复杂            │
│      │ (带约束的优化问题)                        │ 已被 PPO 取代       │
├──────┼────────────────────────────────────────┼────────────────────┤
│      │ Soft Actor-Critic                        │ 连续控制任务        │
│ SAC  │ 最大化: E[回报] + α × H(π)              │ 自动调温度参数 α    │
│      │ (回报大 + 熵大 = 探索充分)               │ 样本效率最高        │
│      │ 温度参数 α 自动调整                      │ 具身智能上效果很好   │
└──────┴────────────────────────────────────────┴────────────────────┘

PPO 的具身智能方程式:

  L^{CLIP}(θ) = Ê_t [ min( r_t(θ) × Â_t, clip(r_t(θ), 1-ε, 1+ε) × Â_t ) ]
  
  r_t(θ) = π_θ(a_t|s_t) / π_{θ_old}(a_t|s_t)     ← 新旧策略比率
  Â_t    = 优势函数 = Q(s,a) - V(s)                  ← 这个动作比平均好多少？
  
  ε = 0.2 (典型值), 比率被限制在 [0.8, 1.2]
  
  训练循环 (具身智能):
    for epoch in range(N_epochs):
        for batch in replay_buffer:
            ratio = new_policy(action|state) / old_policy(action|state)
            advantage = compute_gae(rewards, values)   # 广义优势估计
            loss = -min(ratio * advantage, clip(ratio, 0.8, 1.2) * advantage)
            optimizer.step(loss)
```

### 2.3 价值函数逼近 (Value Function Approximation) — 估计长期价值

价值函数方法估计"从状态 s 出发能获得多少累积回报", 然后选使价值最大的动作。

```
价值函数 V^π(s):
  "遵循策略 π, 从状态 s 开始能获得的期望总折扣回报"
  V^π(s) = E[ Σ γ^k × R_{t+k} | s_t = s ]

动作-价值函数 Q^π(s,a):
  "在状态 s 执行动作 a, 然后遵循策略 π 的期望总回报"
  Q^π(s,a) = E[ Σ γ^k × R_{t+k} | s_t = s, a_t = a ]

两者关系: V^π(s) = Σ π(a|s) × Q^π(s,a)         (对所有动作求期望)
         Q^π(s,a) = R(s,a) + γ × V^π(s')        (即时奖励 + 下一状态价值)
```

**DQN 系列 (深度 Q 网络)**:

```
DQN 核心思想:
  用神经网络 Q_θ(s,a) 逼近 Q*(s,a)
  损失: L = (Q_θ(s,a) - y)^2  其中 y = r + γ × max_{a'} Q_target(s',a')
  
  Q_θ(s,a): 深度卷积网络, 输入 RGB 图像, 输出各动作的 Q 值
  Q_target: 参数定期从 θ 复制 (目标网络, 稳定训练)

DQN 具身智能的问题:
  1. 只能处理离散动作空间 (原有 DQN 的设计)
     → 机器人需要连续动作 (关节角度)
  2. 高维状态过估计 (神经网络倾向于高估 Q 值)
  
  改进 (用于具身):
   DDPG:  连续动作 + Actor-Critic (Deterministic Policy Gradient)
   TD3:   裁剪双 Q 网络减少过估计 (Twin DDPG)
   SAC:   最大熵 + 自动温度 (Soft Actor-Critic)
```

### 2.4 Actor-Critic 架构 — 结合策略和价值的优势

Actor-Critic 是具身智能最常用的架构, 同时学习两个东西: 如何行动 + 行动有多好。

```
Actor-Critic 架构:

  ┌────────────────────────────────────────────────────────────┐
  │                                                            │
  │  状态 s ──┬──→ Actor 网络 (π_θ) ──→ 动作 a              │
  │           │                                                │
  │           └──→ Critic 网络 (V_φ) ──→ 状态价值 V(s)         │
  │                                                            │
  │  执行动作 a, 观察到 (r, s')                                 │
  │                                                            │
  │  优势 Â = r + γ × V(s') - V(s)    ← TD 误差             │
  │           ─────────────   ─────                             │
  │           实际回报(未来)    预期回报                          │
  │                                                            │
  │  Â > 0: 动作比预期好 → Actor 增大该动作概率                 │
  │  Â < 0: 动作比预期差 → Actor 减小该动作概率                 │
  │                                                            │
  │  网络更新:                                                  │
  │    Actor:  ∇_θ log π_θ(a|s) × Â        ← 策略梯度        │
  │    Critic: L = (V_φ(s) - (r + γV_φ(s')))² ← 价值拟合     │
  └────────────────────────────────────────────────────────────┘

Actor-Critic 在具身智能中的工作方式:

  Actor (策略网络):
    输入: s = [joints, vision, touch, imu]  (完整状态)
    输出: μ(s), σ(s)   (高斯策略的均值和标准差)
    采样: a = μ + σ × ε   (ε ~ N(0,1), 探索噪声)
    用途: 输出具体的关节目标角度

  Critic (价值网络):
    输入: s = [joints, vision, touch, imu]  (相同状态)
    输出: V(s)     (当前状态的估计价值)
    用途: 判断当前状态"是好是坏", 引导 Actor 改进

  两者共享底层特征提取器 (可选):
    共享 Backbone (CNN/Transformer) → 视觉特征
    然后分叉为 Actor Head + Critic Head
    → 减少参数, 加快训练
```

## 第 3 部分：具身智能特有的 RL 挑战

### 3.1 高维连续动作空间

```
自动驾驶:       动作 = [转向角, 油门]    → 2 维连续
机械臂:         动作 = [θ1..θ7]           → 7 维连续
人形机器人:     动作 = [θ1..θ30]          → 30 维连续
全身人形:       动作 = [θ1..θ200+]      → 200+ 维连续 (Figure Helix)

  困难: 动作维度越高, 搜索空间指数增长
  解决: 
    - 策略输出对角协方差高斯 (假设各关节独立)
    - 子策略分解: 每肢体一个独立策略网络
    - 行为克隆初始化 (先用人类示范做预训练)
```

### 3.2 延迟奖励 (Delayed Reward)

```
监督学习: 每个样本立即有对错反馈
强化学习: 执行了 50 步动作, 最后才知道成功/失败

  例子: 机器人"倒水"任务
    Step 1-10: 移动到水壶旁      (中间奖励 = 0)
    Step 11-20: 抓住水壶        (触觉检测到抓稳: +0.1)
    Step 21-30: 移动到水杯上方   (接近: +0.05)
    Step 31-40: 倾斜倒水         (水进入杯子: +0.5)
    Step 41:  完成              (成功: +1.0)
    
    问题: 1-30 步的"功劳"如何归因?
    
  解决方案:
    - GAE (Generalized Advantage Estimation): 用 TD(λ) 分配优势
    - 中间奖励塑形 (Reward Shaping): 人为设计中间引导奖励
    - Hindsight Experience Replay: 把失败轨迹也当成功 ("我本意是要拿那个")
```

### 3.3 仿真-现实鸿沟 (Sim-to-Real Gap)

```
训练 100 万步在仿真中:
  P_sim(s'|s,a) ≠ P_real(s'|s,a)
  
  原因:
    仿真: 摩擦系数准确, 传感器无噪声, 延迟确定, 线性刚度
    真实: 摩擦变化, 传感器噪声, 延迟抖动, 非线性/柔性

解决方案:
  1. 域随机化 (Domain Randomization):
     训练时随机化仿真参数:
       friction = U(0.5, 1.5)
       mass = U(0.8, 1.2) × nominal
       latency = U(0, 5ms)
       传感器噪声: N(0, σ)
     → 策略在"最坏情况"下也能工作
     
  2. 系统辨识 (System Identification):
     先让真实机器人执行已知动作
     估计真实参数: M, C, G (质量/科氏力/重力)
     用真实参数更新仿真
     
  3. 在线适应 (Online Adaptation):
     让策略本身有"适应模块"
     输入: 过去 N 步的实际转移 (s, a, s')
     输出: 隐变量 z 编码当前环境特征
     策略: π(a|s, z) → 不仅看状态, 还看"当前环境是什么样"
```

### 3.4 安全探索 (Safe Exploration)

```
普通 RL: 机器人可以试任何动作 (包括破坏自己和周围)
具身安全: 不能让机器人"随便试"

安全措施 (从强到弱):
  1. 物理限制:    关节角度机械限位 + 力矩限制
  2. 速度限制:    关节速度 < 安全阈值 (永远)
  3. 软墙:        workspace boundary 附近渐增强阻力
  4. 人类监控:    操作员持"死亡开关"
  5. 安全 RL 算法: CPO (Constrained PPO) 
     目标: max E[return]  s.t. E[cost] < limit
```

## 第 4 部分：具身智能的 RL 算法选择

### 4.1 决策金字塔中的 RL 位置

```
                    决策金字塔
                    
          ┌─────────────────────────┐
   第 3层 │  大模型任务规划          │ ← LLM/VLM, 慢推理 (1Hz)
          │  "去厨房拿杯子"          │
          ├─────────────────────────┤
   第 2层 │  RL 策略 (中观决策)      │ ← SAC/PPO, 中速 (20-100Hz)
          │  "当前步应移动到哪里"     │
          ├─────────────────────────┤
   第 1层 │  PID/阻抗控制 (低级)      │ ← FOC, 快速 (10kHz)
          │  "电机应输出多少力"        │
          └─────────────────────────┘
```

### 4.2 Phase 1: 行为克隆 → RL 渐进过渡

```
过渡路径:

Phase 1A: 纯行为克隆 ( Behavior Cloning )
  数据: 人类示范 1000 条
  算法: 监督学习 (最大似然)
  结果: 能复现 50-70% 的动作, 失败时崩溃
  原因: 分布外状态无定义

Phase 1B: 行为克隆 + 微调 ( DAgger )
  循环:
    收集当前策略的状态分布
    人类标注这些状态下"正确动作"
    重新训练
  结果: 提升到 80%+
  
Phase 2: 预热 + RL ( Offline-to-Offline )
  数据: 人类示范 + 仿真收集
  算法: IQL / Decision Transformer
  结果: 不优于示范, 但更鲁棒

Phase 3: 在线 RL ( Online RL )
  算法: PPO + 域随机化
  训练: 仿真中 1000 万步 → 真实 10 万步微调
  结果: 可能超越人类示范 (发现新策略)
```

### 4.3 具身智能首选: SAC + 触觉

```
为什么 SAC 特别适合具身智能?

  1. 最大熵目标: 不仅最大化回报, 还最大化策略的熵 (随机性)
     → 机器人保持探索, 不会"卡死"在局部最优
     → 对触觉这种噪声传感器天然鲁棒

  2. 连续动作空间原生: 无需离散化关节角度 (损失精度)

  3. 自动调温: 自动平衡探索 (高熵) 与利用 (高回报)

  4. 高样本效率: 具身成本高, 每个真实样本都"贵"
  
SAC + 触觉输入:
  状态 s = [joints; imu; force_torque; tactile_image]
  
  触觉处理: CNN 或小型 Transformer, 将 tactile_image → feature vector
  
  Actor:  π_θ(joint_targets | joints, imu, touch_feature)
  Critic: Q_φ(joints, imu, touch_feature, joint_targets)
  
  触觉的奖励塑形:
    - 接触检测: if touch_detected then r += 0.1
    - 力控制: if |force - target| < threshold then r += 0.2
    - 滑脱检测: if slip_detected then r -= 0.3
```

## 第 5 部分：代码实现框架

### 5.1 具身 RL 训练循环 (伪代码)

```python
# ===== 具身智能 PPO 训练 =====

class RobotPPOAgent:
    def __init__(self):
        # Actor: 输入状态, 输出动作均值+标准差
        self.actor = SqueezeExcitationPolicy(state_dim=128, action_dim=13)
        # Critic: 输入状态, 输出价值
        self.critic = ValueNetwork(state_dim=128)
        # 共享特征提取
        self.encoder = MultiModalEncoder(
            vision='resnet18',
            proprio_fc=64,
            touch='cnn_4layer'
        )
        
        self.optimizer_actor = Adam(self.actor.parameters(), lr=3e-4)
        self.optimizer_critic = Adam(self.critic.parameters(), lr=1e-3)
        
    def select_action(self, obs):
        """在真实机器人上推理 (每 50ms 调用一次)"""
        features = self.encoder(obs)          # 多模态编码
        mu, log_std = self.actor(features)    # 策略输出
        std = log_std.exp()
        
        # 采样 (训练时), 推理时直接用 mu (确定性)
        if self.training:
            dist = Normal(mu, std)
            action = dist.sample()
            log_prob = dist.log_prob(action).sum(-1)
        else:
            action = mu
            log_prob = None
        
        # 关节角度限制 (-π to π)
        action = torch.clamp(action, -np.pi, np.pi)
        return action.numpy(), log_prob
    
    def train_step(self, batch):
        """从 replay buffer 采样并训练"""
        states, actions, rewards, next_states, dones, old_log_probs = batch
        
        # 计算优势 (GAE)
        with torch.no_grad():
            values = self.critic(states)
            next_values = self.critic(next_states)
            advantages = compute_gae(rewards, values, next_values, gamma=0.99, lam=0.95)
            returns = advantages + values
        
        for _ in range(self.epochs_per_update):
            features = self.encoder(states)
            mu, log_std = self.actor(features)
            std = log_std.exp()
            dist = Normal(mu, std)
            new_log_probs = dist.log_prob(actions).sum(-1)
            
            # PPO 裁剪目标
            ratio = (new_log_probs - old_log_probs).exp()
            clip_ratio = ratio.clamp(1 - 0.2, 1 + 0.2)
            policy_loss = -torch.min(ratio * advantages, clip_ratio * advantages).mean()
            
            # 价值损失
            value_pred = self.critic(features)
            value_loss = ((value_pred - returns) ** 2).mean()
            
            # 熵正则化
            entropy = dist.entropy().sum(-1).mean()
            
            # 总损失
            loss = policy_loss + 0.5 * value_loss - 0.01 * entropy
            
            self.optimizer_actor.zero_grad()
            self.optimizer_critic.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(
                list(self.actor.parameters()) + list(self.critic.parameters()), 
                0.5
            )
            self.optimizer_actor.step()
            self.optimizer_critic.step()
```

## 第 6 部分：RL 与 LLM 的融合 (大模型引导 RL)

### 6.1 为什么纯 RL 不够 + 为什么纯 LLM 也不够

```
纯 RL 的局限:
  - 需要大量试错 (具身代价高)
  - 奖励函数设计困难 (什么叫"好好叠毛巾"?)
  - 难以理解语言指令 (只能从试错学习)
  
纯 LLM 的局限:
  - 不具有物理常识 (摩擦/重力/接触力学)
  - 推理慢 (秒级, 跟不上 20Hz 控制)
  - 没有本体感受 (不知道机器人当前姿态)

LLM + RL = 互补:
  LLM = "大脑" (慢规划, 语言理解, 常识)
  RL = "小脑" (快执行, 精细控制, 力感知)
```

### 6.2 VLA + RL: Action Chunking with Policy Execution

```
Figure Helix 方式 (推测):

步 1: VLM 理解任务 → 输出高层规划 (1Hz)
  "叠毛巾" → [展平毛巾 → 对折 → 再对折 → 放好]
  
步 2: RL 策略执行每个子任务 (20Hz)
  当前子任务: "展平毛巾"
  状态 s = [视觉; 触觉; 关节; 子任务ID]
  RL 策略 π(a|s) 实时输出关节目标
  
步 3: 过渡检测
  if 子任务完成 (触觉不再检测到褶皱):
    更新子任务 ID → RL 切换到下一个子任务流程
    
步 4: 异常恢复
  if 策略失败 (毛巾掉落):
    报告给 VLM → VLM 生成新计划 ("捡起毛巾 → 展平")
```
