# 能力匹配度评审意见 (Capability-Fit Review) v1.0

> **日期**: 2026-10-07
> **评审对象**: `docs/11-production-upgrade-roadmap.md`（生产级升级改造路线图 v1.0）
> **评审视角**: 第三方独立评审 — 回答"路线图目标是否与项目实际能力（以及 AI 可靠交付边界）契合"
> **评审依据**: 全层次审计（EmbodiedAI 251 pass/2 fail 实测 + EdaLab 跨仓库审计）
> **评审结论摘要**: **部分契合**。Phase R/C 大部分可达；**Phase P 全部超出当前能力**；
> **4 项跨仓库/跨语言改造超出单仓 AI 可靠边界**；**路线图遗漏 6 个已确认缺陷，其中 1 个为物理量级错误**。

## 一、项目实际能力基线（诚实评估）

评审前必须先界定"实际能力"，否则路线图目标无法判定可达性。

### 1.1 项目当前客观状态

| 维度 | 事实 |
|---|---|
| 代码形态 | 纯 numpy/scipy 物理与算法原型（65 个 .py）+ Kotlin/Gradle EdaLab 引擎 + 零前端框架 |
| 验收状态 | `pytest` 251 pass / **2 fail**；`verify` **20/22 FAIL** |
| 硬件 | **无真机、无 PCB、无电机、无传感器**（P1-P4 全部依赖外部采购） |
| 仿真 | MuJoCo/PyBullet **非必需**（零依赖 `reference` 后端兜底）；攀岩场景**零覆盖** |
| 测量 | 安全链 16ms 为 EdaLab **常量查表**；VSA 109N 为**公式计算值**；均非物理实测 |
| 版本控制 | EmbodiedAI 有 git（15 文件未提交）；**EdaLab 无 git** |
| 测试 | 单仓 251 项；EdaLab `edalabcore/src/test` **不存在**（build.gradle 配了 test 插件但零测试） |

### 1.2 AI 可靠交付边界（本次评审的能力约束）

**可靠**（可放手交给 AI 执行并验收）：
- 数学推导核对与公式修正（PPO/SAC/FOC/SVPWM/ADMM/力闭合/应变能）
- 代码级缺陷定位与单侧重构（含新增测试）
- 文档—代码一致性审计与口径校正
- 单仓内契约对齐（Python 侧字段/单位/命名）
- 纯软件可验收的仿真/模型工作（如 MJCF 编写并跑通）

**不可靠**（必须人工主导或外部完成）：
- **物理真实性最终判定**（需真实实验：力传感器标定、材料摩擦实测）
- **安全认证的第三方可信度**（ISO 13849/SIL2 需外部审计与实测证据）
- **跨 3+ 语言/仓库的大型一致性改造**（Kotlin + Python + TypeScript 三端字段统一）
- **领域力学参数取值**（crimp/jug 指力、凝胶模量、腱摩擦系数——需攀岩者/材料工程师输入）
- **多版本构建环境搭建与 CI 运维**（EdaLab Gradle/本机 SDK/jar 定位）
- **长期训练与仿真调参**（无稳定 GPU 环境的头less 机器）

| **七、降级砍除清单** | ✅ 认同 | 认同不修 NeRF/VQ/async MCTS。**建议扩大**：见第四节遗漏项中建议新增降级的条目 |

- Phase R: **可执行**（R2/R8 需人工确认）
- Phase C: **可执行**（C4 三端改造需人工主导）
- Phase L: **可执行**（L1/L6 需领域输入，跨度大需拆项）
- Phase P: **不可执行**（超出当前能力，接口已备即可）

## 四、路线图遗漏的已确认缺陷（评审补充，必须并入路线图）

以下 6 项在审计中已确认，但**未被 `11-production-upgrade-roadmap.md` 覆盖**。其中 **V-1 为物理量级错误，优先级应高于路线图中多数 P0**。

| ID | 缺陷 | 证据出处 | 严重度 | 处置建议 |
|---|---|---|---|---|
| **V-1** | **VSA 同一输出两套能量定义差 83 倍**：`stored_energy_j`（零点=平衡位，½Kθ²）与 `curve[].energy_j`（零点=行程边界，∫K dθ）。MACCEPA 0.967J vs 80.67J、SEA 0.638J vs 51.77J、ANTAGONISTIC 0.635J vs 6.30J | EdaLab `VsaVariableStiffnessEngine.kt:160-161` vs `:102-121`；`experiments_vsa_curve.json` | 🔴 **高**（物理量级） | 统一为零点在平衡位的 `∫₀^θ K dθ`；删除或改名 `curve.energy_j`。**当前 EmbodiedAI 只消费 `stored_energy_j` 故未爆，但任何消费 curve 的代码会得到 11.6m/s 致命弹道**。应新增"两套定义差 <5%"测试 |
| **V-2** | **ANTAGONISTIC 刚度模型越界自身声明的 k_min/k_max**：实测曲线 θ=0 时 K=7.16（<k_min=60）、θ=+40° 时 K=527.16（>k_max=520）；V 形曲线意味着一根腱松弛，对拮抗双腱是粗略近似 | `VsaVariableStiffnessEngine.kt:140-143` | 🟠 中 | 修刚度模型或修正 k_min/k_max 声明；`hw_requirements.yaml` 依赖此参数 |
| **V-3** | **VSA 采样网格未对齐弹性行程边界**：25 点均分全行程，ANTAGONISTIC(80°) 步长 3.33°，span 过滤只采到 6.67°（弹性行程 12° 的一半）→ **跨拓扑蓄能/弹速比较不公平**（MACCEPA 只在 3.75° 评估） | `VsaVariableStiffnessEngine.kt:148-154, 200-202` | 🟠 中 | 采样点显式钉住 ±elastic_travel/2；影响"109N 为何最优"的论证基础 |
| **V-4** | **torque_max_nm 语义颠倒**：`Pair(springT+(reg+ctrl), springT−(reg+ctrl))` 在 θ<0 时"max"实为较小值，JSON 只导出该字段 | `VsaVariableStiffnessEngine.kt:148-154` | 🟡 低-中 | 改 `max(of(springT±(reg+ctrl)))` |
| **V-5** | **DR 摩擦系数分布冲突**：飞轮产出 `uniform[0, 2σ(I)]`，契约标定 `normal(0.8, 0.15)` 且被机会约束握力依赖 → 飞轮回写会**覆盖**精心标定的 μ 分布为 `[0,0]` | `ManufacturingDataFlywheel.kt:203-207` vs `contracts/dr_params/manufacturing_variance.yaml` `sensing.friction_coefficient` | 🟠 中 | 明确"标定优先，飞轮只更新 loc 不更新 shape"或统一口径；补分布一致性测试 |
| **V-6** | **v_capture_max 三方口径不一**：契约 0.433m/s（A3 自有）、`vsa_coupling.capture_feasibility()` 默认参数算得 0.164m/s（休眠，无人调用）、VSA 实际 1.07m/s | `contracts/hw_requirements.yaml:140`、`vsa_coupling.py` capture_feasibility | 🟡 低 | 统一或明确各自适用条件；`capture_feasibility` 若不用应删除（休眠地雷） |

## 五、放行分级建议（Gate 意见）

基于能力匹配度，建议设置 5 道放行门，每道门有明确口径，避免"未达生产级却宣称生产级"：

| Gate | 达成条件 | 可对外宣称 | 当前 |
|---|---|---|---|
| **Gate 0**（现在） | README 口径诚实化（C6）+ 明确"生产级缺口声明" | "研究级工程蓝本 / Phase A 设计" | ✅ 可放行（诚实化后） |
| **Gate 1** | Phase R 全完成（verify 22/22 绿 + 安全去循环 + 路径解耦 + CAN 对齐） | "可复现的工程原型" | ❌ 未达（2 fail + 本机路径） |
| **Gate 2** | Phase C 全完成（默认配置不残废 + 契约两端自动化测试守护） | "契约自洽的仿真平台" | ❌ 未达 |
| **Gate 3** | Phase L 全完成（攀岩仿真可 step + 触觉闭环 + MCTS 真实目标 + 灵巧手攀岩任务集，**且领域参数已由专家填入验证**） | "仿真闭环的攀岩具身原型" | ❌ 未达 |
| **Gate 4** | Phase P 全完成（安全数值实测注入 + 真机四步通电 + 双仓库 CI + 性能实测） | **"可上真机的产品"** | ❌ 未达（硬件未到） |

**评审特别意见**: Gate 3 与 Gate 4 之间不是"再修几个 bug"的关系，而是**从仿真到物理的质变**。当前所有工作（Phase R/C/L）都在 Gate 3 及以下，**不要在 Gate 3 完成前对外承诺任何"可上真机"的时间表**——因为 Gate 4 的关键路径是硬件采购与实测，不受代码质量控制。

## 六、评审结论

1. **路线图整体方向正确**：Phase R→C→L→P 的递进依赖判断正确（验收链是红的前提下一切无效），每条任务绑定审计证据，质量高于一般规划文档。

2. **但存在两类不契合**：
   - **能力不契合**：Phase P（8 任务）全部超出当前项目与 AI 的执行条件；C4/L6/R8 需人工主导。建议路线图显式标注"待外部条件/待人工确认"，避免被当作可立即执行的 sprint。
   - **完整性不契合**：遗漏 6 个已确认缺陷（V-1~V-6），其中 **V-1（VSA 能量双定义差 83 倍）是物理量级错误，优先级应高于路线图中已列的多数 P0**——它一旦被下游消费会导致 11.6m/s 的致命弹道。另有 `capture_feasibility` 休眠函数（0.164 口径）属潜在地雷。

3. **最小可行起步路径（能力匹配的最短路径）**：
   - **立即可做（AI 可靠，1-2 周）**：R1（verify 转绿）+ R3（路径解耦）+ R4（CAN 对齐）+ R7（机会约束）+ V-1/V-4（VSA 能量口径）→ 达到 Gate 1
   - **需人工主导（2-4 周）**：R2（安全链，需决策"改名 assumed"还是"接物理模型"）+ C4（三端命名，需统一提交）
   - **需领域输入（1-3 月）**：L1（场景物理参数）+ L6（灵巧手攀岩力学参数）
   - **不可排期**：Phase P（等硬件）

4. **一句话结论**：**这份路线图对"代码能做什么"评估准确，对"项目/AI 能交付什么"评估偏乐观**。建议按本评审的第二节评级调整各阶段排期，并把第四节的 V-1~V-6 并入路线图，其中 V-1 提为 P0。
